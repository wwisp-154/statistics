# Concept Learning Guide

生成一份**克制、可溯源、带递进自测题**的概念学习资料（单文件 HTML）。核心理念：少即是多——概念要少、文字要少、颜色图标要少，把认知负荷压到最低。

## 适用场景

- 学习一个新概念（技术名词、方法论、学科概念），需要一份可日后复习的资料
- 资料要求可溯源：每个论断能点回原始出处验证
- 资料要求克制：文字少、颜色少、图标少，低认知负荷
- 不适用：需要长篇系统性教材、需要多文档协作、或不需要溯源的场景

## 输入

必需：**一个概念名**（如 "Agent"、"大模型的上下文"、"Skill"）。
可选：用户指定的资料来源；若未指定，按第 1 步的优先级自行溯源。

## 生成步骤

### 第 1 步：溯源（必须先做，不可跳过）

用 WebFetch 抓取概念的**原始出处**，2-3 个即可，按优先级：

1. 提出该概念的官方首发文章/工程博客（如 Anthropic 工程博客）
2. 官方规范/标准站点（字段、数值、约束以规范为准）
3. 官方文档或高被引的一手综述（如 Lilian Weng 博客）

注意：跟进重定向（WebFetch 会报告新 URL）；抓取时要求"保留原文准确表述与数值"；若文档站因地区限制失败，换规范站或 GitHub 源。**不得凭记忆编造字段名、数值、引文**——所有论断必须来自抓取结果。

### 第 2 步：提炼（删到不能再删）

提炼的起点：先为该概念写下 **3-5 条可检验的学习目标**（学完后能做什么/能解释什么）和 **1 个贯穿全篇的核心问题**（这个问题被回答，概念就掌握了），作为资料的第 0 节。然后从原始资料中提炼 **4-6 个章节**，每章只讲一个概念：

0. **学习目标与核心问题**：见上
1. **一句话 + 个人解释**：用一句加粗大字定义概念，配一个"像什么"的类比；另用 1-2 句写"我的理解"（用自己的话，标注与原文的差别）
2. **核心机制**：一张 SVG 图（机制/流程/分层）
3. **应用场景**：一个具体、真实的应用场景（有出处优先）
4. **易混淆与边界**：1-2 组最常见的混淆概念，说清区别与适用边界
5. **自测**：6 道题（见第 4 步）

### 第 3 步：生成 HTML

基于 `assets/template.html` 骨架填充。设计铁律：

- **配色**：只用 1 个强调色（默认赭橙 `#c15f3c`）+ 墨色/灰/纸底，禁止第二彩色、禁止装饰性图标、禁止 emoji
- **文字**：每节正文 ≤ 3 行 lead，细节全部下沉到 SVG 图注或出处链接
- **SVG**：viewBox 680 宽，扁平矩形+文字，无渐变阴影立体效果
- **溯源**：每个章节末尾有 `出处 · <a target="_blank">` 链接行，全部原始出处汇总在页脚；测试题解析末尾附"回原文验证"链接
- **链接**：一律 `target="_blank"`，用户可点击验证每个论断

### 第 4 步：测试题（难度必须递进）

固定 6 题，星级标注：

| 星级 | 数量 | 考什么 | 示例 |
|------|------|--------|------|
| ★☆☆ | 2 | 记忆：定义、组成 | "是什么""包含哪几种" |
| ★★☆ | 2 | 理解：机制、时机、好 vs 坏对比 | "何时加载""哪种写法更好" |
| ★★★ | 2 | 应用/辨析：为什么、反直觉点、使用边界 | "为什么这样设计""该用 A 还是 B" |

交互：单击选项即锁定——正确项高亮强调色，错选项划线置灰，显示解析；解析末尾附溯源链接。干扰项要来自原文中真实的"错误示例"或常见误解，不编造。

### 第 5 步：自检与交付

文件名 `{概念名}-学习资料.html`，写入目标目录后用 present_files 展示。

## 输出结构（自检清单，逐项核对后才算完成）

| # | 必含元素 | 检查方法 |
|---|----------|----------|
| 1 | 学习目标与核心问题 | 有 3-5 条可检验的学习目标 + 1 个贯穿性问题 |
| 2 | 概念的个人解释 | 有"一句话 + 我的理解"节，且与原文表述有区分 |
| 3 | 核心机制或组成 | 有一张 SVG 图，图注可溯源 |
| 4 | 一个具体应用场景 | 场景真实、有出处优先 |
| 5 | 容易混淆的问题/使用边界 | 至少 1 组混淆概念说清区别 |
| 6 | 可核查的资料来源链接 | 每节末尾 + 页脚均有可点击的原始出处 |
| 7 | 6 道递进测试题 | ★☆☆×2 → ★★☆×2 → ★★★×2，交互可判分 |
| 8 | 设计克制 | 仅 1 个强调色；无装饰图标；每节正文 ≤ 3 行 |

任何一项不满足，回到对应步骤修补后再交付。

## 模板

`assets/template.html` 包含全部 CSS（配色变量、章节结构、字段列表、测试题交互 JS）。生成时：读入模板 → 替换内容 → 保留 CSS 与 JS 结构不动。只有当模板确实不满足需求时才修改其样式，且仍须遵守第 3 步的设计铁律。
