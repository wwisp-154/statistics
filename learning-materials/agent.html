Concept · Study Note 01

Agent（智能体）

读四节，答六题。每个论断都能点回原始出处验证。
01 / 个人解释

一句话

Agent 是让 LLM 自己决定流程的系统；流程写死在代码里的，叫 Workflow。

我的理解：把 LLM 想成一个新员工——Workflow 是给他一张写死的流水线操作单，Agent 是给他一个目标和一套工具，让他自己想办法。员工能干多好，取决于两件事：他每一步能看到什么信息（上下文），以及有没有前人留下的操作手册（技能）。
原文定义：Workflows 是 "LLMs and tools are orchestrated through predefined code paths"；Agents 是 "LLMs dynamically direct their own processes and tool usage"。

出处 · Anthropic《Building effective agents》（2024-12）↗

02 / 核心机制

LLM 是大脑，三个组件环绕

Lilian Weng 给出的经典架构：LLM 作为 agent 的 brain，配上三种关键组件。

两份原始出处用的是同一张图的两种画法：Planning / Memory / Tool use 三组件，在 Anthropic 文中即 retrieval、tools、memory 三种增强。

出处 · Lilian Weng《LLM Powered Autonomous Agents》（2023-06）↗　Anthropic §Augmented LLM ↗

03 / 应用场景

一个具体场景：让 Agent 修一个 Bug

用户只说「登录接口报 500 了，帮我修」。没有固定路径可写——这正是 Agent 的地盘：

① 自己看报错读日志 → 怀疑是数据库连接超时（模型自主决定先看什么）
② 自己查代码用检索工具定位到连接池配置文件（Tool Use）
③ 自己做实验跑测试脚本复现问题 → 改配置 → 再跑测试验证（Planning 的反思环节）
④ 自己收尾提交修改并写清原因——每一步用哪个工具、走不走回头路，都是模型根据反馈现场决定的

对应的反面：如果需求是「每天凌晨把 CSV 转成固定格式报表」，步骤完全可预测，写死的 Workflow 更便宜、更稳定。

出处 · Anthropic：Agent 适用于 open-ended problems，"difficult or impossible to predict the required number of steps" ↗

04 / 易混淆与使用边界

两个最容易搞混的点

Agent ≠ 聊天机器人 聊天机器人只回答对话；Agent 能采取行动（调工具、改文件、执行代码）并根据结果继续。判断标准是「有没有行动闭环」。
Agent ≠ 越强越好 原文反复强调：最成功的实现用简单、可组合的模式。Agent 的自主性意味着更高成本和累积误差（compounding errors），需要沙盒测试与护栏（guardrails）。能不用就不用。

出处 · Anthropic §Agents（成本、compounding errors、guardrails）↗
