Skill（技能）

读四节，答六题。每个论断都能点回原始出处验证。
01 / 个人解释

一句话

一个 Skill = 一个文件夹，里面放一个 SKILL.md，教智能体完成一类任务。

我的理解：Skill 就像给新员工写的一份入职手册——把老师傅的经验（流程、坑、脚本）整理成文件。手册放在书架上（不占脑子），员工接到相关任务时才翻出来看，看完就能上手。这解决的是「同一个本事不用每次现教」的问题。

02 / 核心机制

渐进式披露：三层，按需加载

这是唯一需要记住的机制。智能体不会一次读完——像查手册：先看目录，再看章节，最后翻附录。

上下文占用从上到下递增。规范给出的 token 预算：元数据约 100，SKILL.md 正文 < 5000，资源按需。

03 / 应用场景

一个具体场景：官方的 PDF 技能

处理 PDF 是个典型任务：提取文本、填表单、合并文件——每次现教太浪费，于是打包成一个技能：

pdf/技能目录，name 就叫 pdf-processing 一类
SKILL.md写清"能做什么 + 何时用"：处理 PDF 文档时触发
scripts/extract.py提取脚本——智能体直接运行它，脚本和 PDF 都不用读进上下文，结果确定、可重复
forms.md填表单的详细指令——只有真正要填表时才被读入

效果：没有 Skill 时每次都要从零教；有了 Skill，10 个不同产品里的智能体都能"上岗即会"。

04 / 易混淆与使用边界

两个最容易搞混的点

Skill ≠ MCP MCP 是连接外部系统的协议（提供"入口"）；Skill 是教智能体怎么用好这些工具的工作流知识（提供"会干"）。原文明确：Skill 是对 MCP 的补充（complement），不是替代。
Skill ≠ 长期记忆 / RAG 记忆和 RAG 存的是"事实与历史"，靠相似度检索；Skill 存的是"程序性知识"（怎么做一件事），靠 name + description 判断触发。一个回答"是什么"，一个回答"怎么做"。
